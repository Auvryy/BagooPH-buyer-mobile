Start: merged buyer main `5b021f2`; initial branch `fix/buyer-misuse-regressions`; current continuation branch `fix/buyer-search-price-input-validation`.

## Scope and acceptance

Exercise every implemented buyer feature family against invalid input, repeated actions, failed requests and stale identity. Reproduce confirmed client bugs with isolated regression tests before fixing them. Use synthetic repositories, never production accounts or shopping mutations. This coding pass excludes phone, browser, and visible-screen control. Backend source and configuration remain read-only.

Acceptance requires a coverage record for each family, passing formatting/analysis and the full isolated suite. Client checks must match existing server rules; server authorization, stock, payment and order state remain authoritative. Native UI interaction, provider, OS permission and real device acceptance are separate evidence and must not be inferred from isolated tests; they remain deferred for this pass.

Product detail: reproduced an Add to Bag response restoring the previous buyer's page and success message after the session changed. ## Input validation continuation findings

Profile's decimal amount keyboard accepted malformed typed or pasted values because its shared form helper only selected formatters for phone and integer keyboards. It now uses the existing unsigned decimal formatter. Checkout's manual latitude/longitude fields also lacked an edit formatter: malformed values were caught on Review order, but stayed in the visible fields. They now retain the last valid edit for malformed text while preserving signed values, a trailing decimal during editing, and up to seven fractional digits; range, paired-coordinate and incomplete-value checks still happen at review.

Several text fields only checked required/minimum/maximum length even though the existing backend applies `ApplicationText` rules. Added pre-submit checks for Latin-script names, address/location punctuation, and plain-text notes, including hidden/control characters and markup-like payloads. Identity corrections now use the field's server-supplied length bounds, and postal-code application fields use ASCII digits. Tests cover valid accented/full-width input where the backend normalizes it, invalid names/markup/control characters, pasted numeric edits, and direct-controller bypass. This is client feedback only; server validation remains authoritative.

Return request descriptions and return action reasons had the same length-only gap against the backend's notes rule. They now use the shared pre-submit notes check. The focused return-action suite passes 24 cases, including markup, unsafe schemes, tabs, hidden characters, and direct-controller attempts on both submit paths.
